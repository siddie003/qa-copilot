How QA Copilot tests a website

QA Copilot crawls a website in a real browser, runs seven automated QA scanners, compares the pages with the project's Figma design, brand guidelines and approved content, and turns the evidence into grouped issues and reports. This page shows the workflow, the scan pipeline, the system architecture and the technology used.

TypeScript monorepo 2 apps · 10 packages Node.js 22 PostgreSQL Playwright · Chromium

1. What the tester does

The setup wizard collects the six inputs. Extracted design values stay a draft until someone confirms them; a scan uses the references exactly as they are when it starts.

Six inputs

Website URL, brand guidelines, font files, Figma design URL, content documents and page links.

Readiness guard

Start QA Scan stays disabled while the design draft is unconfirmed or sources are still processing, unless the tester ticks "Start anyway".

Re-scans

Issues keep their identity across scans, so a fix shows as Resolved only when a later scan no longer finds it.

3. System architecture

Two processes share one PostgreSQL database. The web app accepts requests and queues work; the worker picks it up immediately through PostgreSQL LISTEN/NOTIFY and does all crawling, browser work and calls to Figma and the AI provider.

  U["Tester's browser"] -->|HTTPS| WEB
  subgraph WEB["Web app · Next.js 16 + React 19"]
    direction TB
    UI["Pages and forms
Tailwind CSS"]
    API["REST API /api/v1
Zod validation, rate limits"]
    AUTH["Better Auth
email and password sessions"]
  end
  WEB -->|"Drizzle ORM"| DB[("PostgreSQL
projects, scans, findings, issues,
references, job queue")]
  WEB --> ST[("File storage
uploads, screenshots,
snapshots, reports")]
  DB <-->|"LISTEN / NOTIFY"| WK
  subgraph WK["Worker · Node.js"]
    direction TB
    SW["Scan worker"]
    RW["Reference worker
Figma, guidelines, documents"]
    PW["Report worker"]
  end
  WK --> ST
  SW --> BR["Playwright · Chromium
headless, guarded"]
  BR --> GP["Network guard proxy
blocks private and internal addresses"]
  GP -->|"normal page requests"| SITE["Website under test"]
  RW -->|"REST API, token in .env"| FIG["Figma API"]
  SW -->|"optional"| LLM["AI provider
Gemini, Anthropic, OpenAI-compatible, Groq"]

Safe by default

Every outgoing request goes through SSRF rules: scans cannot reach private networks, and only normal page requests are made.

Secrets stay server-side

Figma and AI keys live in .env or are encrypted per project; they are never sent to the browser.

Quota aware

Figma reads check the file version first, and AI calls are paced to the provider's free-tier limits.
