Where QA Copilot's capacity limits come from, and how to raise them

An analysis of Figma, the AI layer and QA Copilot's own processing limits, based on the current code, measurements from the Ascendion scans (22 and 24 October 2026) and the providers' official pages read on 24 October 2026.

confirmed official documentation observed measured on our installation estimate derived, assumptions stated our app a limit set in QA Copilot's code or configuration

1. Executive summary

The AI context window is not the bottleneck

QA Copilot never sends a whole website, Figma file or screenshot to the AI. It sends grouped issue evidence as text, at most about 20,000 input tokens per request. The binding AI limits are requests per minute and per day, and on the free tier, Google's data-use terms.

Figma's limit depends on the seat in the file's plan

With a View/Collab seat, file reads are capped at "up to 20 per month" on every plan. The limit belongs to the plan where the file lives. Buying our own Figma plan does not raise the limit for a client's file (such as Ascendion's).

Most of the analysis does not use AI at all

Seven deterministic scanners produce the findings. AI only rewrites issue text, and that text is checked against the evidence. When AI is unavailable, the scan still completes with the scanners' wording.

AI cost per scan is cents

The 24 October scan (17 pages, 75 issues) used about 130,000 input and 46,000 output tokens. On paid tiers that is about $0.04 (Claude Haiku 5.5) to $0.72 (Claude Sonnet 5.5) per scan. Gemini 3.6 Flash is about $0.27.

Our own code sets the hard ceilings

At most 500 pages per scan, 300 checked links, 200 AI-explained issues, one Figma link per project and one merged design reference. These are design choices, not subscription limits, and only code changes raise them.

Spend on architecture before subscriptions

The highest-value next steps are code: reuse AI text for issues already seen, a provider fallback chain, per-template design references, scan resume and a usage/cost dashboard. Paid AI is only needed for client data (Google's free-tier terms) and higher daily volume.

Is one Figma URL for the whole website practical?

For reading: yes. QA Copilot can read a 53-page file through one URL, in batches of 10 pages, with resume. That costs about 7 Tier 1 requests the first time and none while the file is unchanged.

For accurate comparison: no, not today. The tool keeps one value per role, so every website page is compared with one blended design. The accurate setup is one project per template, each with one frame link (for example T16 → articles, T1 → home), or the per-template design references proposed in section 8.

What drives AI usage in QA Copilot

InputSent to AI?Effect on AI usage
Number of website pagesNo (indirectly)More pages mean more findings, but findings are grouped into issues by rule. The 24 Oct scan turned 846 findings into 75 issues, so usage grows much slower than page count.

ScreenshotsNoStored as evidence (about 66 MB per 17-page scan) and never sent to AI.
Brand guidelinesOptional, cappedA deterministic reader extracts values. An AI pass over guideline text is capped at 300 lines / 40,000 characters.
Font filesNoValidated by code.
Content documentsOnly relevant sectionsSplit into sections of about 600 tokens. Only sections matching an issue are attached, each cut to 800 characters.
Issue evidenceYesUp to 10 issue groups per request, 5 findings per group, values trimmed, about 20,000 input tokens per request, 200 issues per scan.

What happens at a limit

  • Input too large for one request: batches are cut to fit before sending. An issue that still does not fit keeps the scanners' wording, with the reason recorded. our app
  • Per-minute limit (HTTP 429): client-side pacing waits for a free slot. The Retry-After wait is honoured up to 60 s, with 3 retries. our app
  • Daily quota used up: detected from Google's structured quota ids. The remaining issues keep the scanners' wording, and the AI step says so. Nothing is lost, but there is no automatic switch to another provider. our app
  • Provider overloaded or down (HTTP 503, timeouts): retried. On 24 Oct, 3 of 12 requests still failed with HTTP 503 "high demand", so 19 issues used the scanners' wording. observed
  • AI says something the evidence does not support: the grounding check replaces or rejects it. On 24 Oct, 843 of 867 checks passed and 16 issues had unsupported parts replaced. observed

Handled today
Read page by page (10 per batch, split on "too large", version-pinned, checkpointed). A single page over 50 MB is marked failed and the rest continue.
Better
Link the frames that matter (1 read) instead of the whole file

7. AI quota reached during a scan

Handled today
Scan completes. The remaining issues use the scanners' wording and the AI step reports it (seen on 22 Oct).
Better
Provider fallback chain (for example Gemini → Claude Haiku 5.5), and reuse of AI text for issues already seen

8. Figma throttled or incomplete data

Handled today
Short waits retried. Long waits (44 h seen) stop the read with a checkpoint and partial draft. Missing pages are listed, and unchanged files are not re-read.
Better
A Dev seat in the client's plan, or a copy of the needed frames in our own Professional team

The current design already meets most of the requirements:

  • multi-project support, all six input types and evidence-backed findings;
  • the three verdict states (confirmed, potential, unable to verify);
  • a provider abstraction, Figma resume and token logging.

Five additions close the gaps:

  • per-template references;
  • an AI text cache;
  • a model router with a fallback chain;
  • step-level scan resume;
  • a shared rate limiter with a cost dashboard.

None of them needs a new subscription.

9. Prioritized roadmap

Immediate (days, config or small code)

  1. Move client scans to a paid AI tier (Gemini Tier 1 or Claude Haiku 5.5). Under Google's terms, free-tier content may be used to improve products and read by human reviewers.
  2. Usage and cost dashboard from the existing ai_run data.
  3. Reuse AI text for issues already seen in earlier scans.
  4. Link Figma frames, one project per template; avoid whole-file reads.
  5. Store the second provider's key; set AI_REQUESTS_PER_MINUTE to the paid tier's limit.

Medium term (weeks)

  1. Provider fallback chain on daily quota and 503.
  2. Per-template design references (frame ↔ URL pattern).
  3. Model routing (cheap vs strong).
  4. Screenshot compression and retention policy.
  5. Agree Figma access with clients: a Dev seat in their plan, or frames copied to our team.

Enterprise scale (months)

  1. Step-level scan resume and retry of single steps.
  2. Shared, database-backed rate limiter for many workers.
  3. Batch API mode for overnight scans (50% cheaper).
  4. Per-client quotas and priority queues.
  5. Splitting sites over 500 pages into section projects automatically.

  • Gemini free-tier daily limit: not published by Google; about 20/day observed. If a scan needs more than the day's remainder, the rest of the issues keep the scanners' wording. Check AI Studio → Rate limits.

  • Figma Enterprise Tier 1 values and Groq free-plan values could not be read reliably from the official pages; check the account consoles.
